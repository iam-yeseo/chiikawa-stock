# Market data implementation notes

Official schemas checked 2026-10-20 (REST version 1.2.24 for the 0.3.0 account feature). Automated account tests use public-schema fixture responses, never personal credentials or live account data.

- [REST OpenAPI schema](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)
- [WebSocket AsyncAPI schema](https://openapi.tossinvest.com/openapi-docs/latest/asyncapi.json)
- [Integration guide](https://openapi.tossinvest.com/openapi-docs/overview.md)
- [Official FAQ](https://openapi.tossinvest.com/openapi-docs/faq.md)

`POST /oauth2/token` uses URL-encoded `client_credentials`, `client_id`, and `client_secret`. Access tokens live only in the main process memory. `token-revoked`, invalid credentials, and IP denial stop reconnects; they do not create a token issuance loop. A proven `expired-token` response allows one renewal. REST and WebSocket hosts are fixed, and redirects are rejected.

`GET /api/v1/prices?symbols=...` returns `{result:[{symbol,timestamp,lastPrice,currency}]}`. It has no previous-close field. The app obtains the latest earlier trading-day candle from `GET /api/v1/candles?symbol=...&interval=1d&count=10&adjusted=true`; its `closePrice` supplies the previous-close baseline. The FAQ states that US daily OHLC uses official regular-session prices. KR prices/candles aggregate KRX and NXT. Corporate-action adjustments follow Toss's documented adjusted-candle rules; small US cash dividends may not be adjusted. These values need not match an unadjusted historical close displayed by another vendor.

Trading-day selection uses Asia/Seoul for KR and America/New_York for US, including DST. The FAQ defines the US trading day as the previous NY date at 20:00 through the named date at 20:00. The application therefore advances the US date at 20:00 and selects a daily candle strictly earlier than that trading day. A missing previous candle yields a null percentage and no threshold alert; the app never substitutes a guessed previous close. Price timestamps are the source timestamps. More than 120 seconds without a recent source price is explicitly stale, including closed markets. Repeated retrieval of an old last trade does not make it fresh.

The seven exchange catalogs (`KOSPI`, `KOSDAQ`, `NYSE`, `NASDAQ`, `AMEX`, `KR_ETC`, `US_ETC`) are loaded from `/api/v1/stocks/all`, paced above one second per request, then cached in memory for a day. Catalog loading begins when searching in live mode; demo/offline searches use only the bundled starter selection. The 20 starter stocks are a curated initial list, not a current market-cap ranking.

`wss://openapi-ws.tossinvest.com/ws/v1` receives a full replacement subscription array of `trade:kr` and `trade:us` symbols. Trade payloads use `data.price`, `data.currency`, and `data.timestamp`. All sessions supported by Toss are included: US premarket, regular, afterhours, and day market; KR KRX regular plus NXT premarket, regular, and afterhours. The API describes these feeds as lossy, without replay or sequence IDs, and US sources do not represent every exchange/NBBO. Thus 'immediate' means on receipt of a delivered threshold-crossing trade; a disconnected or lost transient crossing cannot be guaranteed. REST reconciles every minute and after reconnect. Initial or recovered samples establish alert state silently. `PING` is sent every 60 seconds. Failed reconnection attempts use exponential backoff capped at 60 seconds and stop after 8 consecutive attempts; stable connections reset the count. Rejected symbols are excluded from later subscriptions until the watchlist changes.

Demo mode is synthetic and visibly labeled. Its tracking baselines never persist into the live configuration. Per-user API credentials and data are never shared through an application server. This architecture is not a certification of Toss's third-party app distribution terms; those terms and character asset redistribution rights remain a release consideration.

## Account and stock assets in 0.3.0

`GET /api/v1/accounts` returns `Account[]` with `accountSeq`, `accountNo`, and `accountType`. `GET /api/v1/holdings` receives `X-Tossinvest-Account: {accountSeq}`, never the account number. Both reuse the exact main-process `TossClient` token already used by quotes; account access does not issue an independent token. Only these read-only endpoints are added. There are no order, transfer, or cash-balance calls. “Assets” in this UI means the stock-holdings overview supplied by this endpoint, not the user's entire cash-inclusive balance.

The official integration guide limits `ACCOUNT` to 1 request/second and `ASSET` to 5 requests/second. Separate queues use 1100 ms and 220 ms spacing, with existing bounded `429`/`Retry-After` handling. The account and holdings overview refresh at startup, every 60 seconds, and on a manual refresh. Account changes invalidate in-flight results immediately. Market quotes and their existing n-minute bulletin schedule remain independent of account-only errors. A proven revoked/invalid shared token still stops monitoring to avoid repeated token issuance.

`HoldingsOverview` amounts are decimal strings. `Price.krw` sums only KRW holdings and `Price.usd` only USD holdings; they are never added together or silently currency-converted. The SDK's overview `rate` is an aggregate return on its KRW-converted basis. All `rate` fields are fractional ratios (`0.1077` → `10.77%`), converted once in normalization. Null/invalid/absent values remain null, not zero. Fractional quantities remain fractional. Tax may be null. Unknown market/currency or malformed item rows are omitted with an explicit unsupported-item count. Empty accounts and zero holdings are valid empty states.

Only masked account labels (last four digits) and account sequence IDs reach renderer snapshots. Account IDs, quantities, money amounts, raw account responses, and account selection are never written to settings. Refresh errors retain the same selected account's last successfully normalized holdings with a stale/error indicator; stop, credential/mode changes, and selecting a different account clear them. Server payloads, raw errors, and account numbers are not logged or displayed.

`autoWatchHoldings` defaults to true on migration. Positive-quantity KR/US holdings append to the existing watchlist, deduplicated by market and symbol. Existing names and manually entered baseline prices remain unchanged. The 100-stock cap preserves existing entries and exposes the omitted count rather than silently claiming complete monitoring. Auto-added stocks use the normal REST/WebSocket quote path, immediate 5% crossings, and n-minute bulletins; currently held stocks are announced first. Turning auto-add off stops future additions without deleting entries. Removing a currently held stock while auto-add is on adds it back; turn auto-add off first to exclude it.

For the purchase-price baseline, an explicit manual watchlist price takes precedence. If absent, the current selected account's API average purchase price is used at quote evaluation time. This fallback is kept in memory and updated from fresh holdings; an imported average is never frozen into settings. All other baseline modes retain their original meaning. Demo holdings are synthetic Samsung/AAPL examples and a second empty account. Any demo-only auto-additions are filtered by `getPersistedConfig()` and removed when leaving demo; they cannot contaminate the live watchlist through appearance/settings saves.
