# 0.2.1 멀티모니터 드래그

0.2.1은 캐릭터를 잡아 다른 모니터로 끌어 옮길 때 현재 화면 경계에 갇히던 동작을 수정합니다. 화면 안에서 움직이는 위치뿐 아니라 투명 펫 창이 올라갈 모니터도 드래그 중에 변경합니다. 트레이의 **보낼 모니터** 기능은 그대로 유지합니다.

## 좌표와 역할

위치 계산은 `electron/pet-drag.js`의 `PetDragController`가 담당합니다. Electron의 전역 커서, 디스플레이 경계, 창 위치는 모두 DIP(device-independent pixels)로 취급하며, `scaleFactor`를 곱하거나 나누지 않습니다.

렌더러는 드래그 시작 시 세션 ID, 캐릭터 크기, 캐릭터 안에서 잡은 지점의 오프셋만 전달합니다. 네이티브 드래그 중에는 렌더러의 `clientX`/`clientY`로 다시 위치를 계산하지 않습니다. 모니터가 바뀌면 창의 원점도 바뀌기 때문에 이전 창의 로컬 좌표를 새 창에 적용할 수 없기 때문입니다.

메인 프로세스의 흐름은 다음과 같습니다.

1. `webContents`의 `before-mouse-event`에서 받은 `globalX`/`globalY`를 시작·이동·종료 위치에 우선 사용합니다. 별도로 16ms 주기로 `screen.getCursorScreenPoint()`를 읽어 렌더러의 포인터 이벤트가 끊겨도 계속 추적합니다.
2. `lib/pet-geometry.js`의 `displayForPoint()`로 전역 커서가 포함된 디스플레이를 선택합니다. 공유 경계는 왼쪽·위쪽을 포함하고 오른쪽·아래쪽을 제외합니다. 모니터 사이 빈 공간에서는 사각형 경계까지 가장 가까운 디스플레이를 선택하고, 거리가 같으면 직전 디스플레이를 유지합니다.
3. 필요한 경우에만 펫 창을 대상 디스플레이의 `workArea`로 옮깁니다. 실제 `getContentBounds()` 원점과 잡은 지점의 오프셋을 전역 커서에서 빼서 로컬 위치를 구하고, 말풍선과 캐릭터를 위한 여백 안으로 보정합니다. 음수 화면 원점과 작은 작업 영역도 같은 기하 함수로 처리합니다.
4. 세션 ID와 증가하는 순번을 담은 배치 패킷을 렌더러에 보냅니다. 렌더러는 다른 세션이나 이전 순번을 무시하고 메인 프로세스의 위치를 적용합니다.

네이티브 전역 좌표를 얻을 수 없는 이벤트는 메인 프로세스가 읽은 전역 커서로 계산합니다. 브라우저 미리보기와 터치 입력은 기존 로컬 드래그를 사용합니다.

## 종료와 정리

모니터 전환 중 `lostpointercapture`가 발생해도 네이티브 드래그를 곧바로 종료하지 않습니다. 네이티브 마우스 놓기 이벤트 또는 렌더러의 종료 요청을 받아 마지막 위치를 한 번 더 적용한 후, 최종 패킷과 함께 세션·주기 타이머를 정리합니다. 오래된 세션의 종료 요청은 새 드래그를 종료하지 않습니다.

종료 후에는 투명 창의 클릭 통과를 복원합니다. 커서가 캐릭터 위에 남아 있으면 렌더러가 해당 위치의 상호작용을 다시 확인하므로 이어서 잡을 수 있습니다. 숨기기, 창 닫기, 렌더러 종료·새로고침, 모니터 제거, 절전, 앱 종료도 드래그 정리 경로를 사용합니다. 30초 제한 타이머는 종료 이벤트가 누락된 세션을 해제합니다.

## 검증한 범위

2026-10-20 기준 전체 단위 테스트 **54개가 통과**했습니다. 드래그와 좌표 관련 검증은 `tests/pet-drag.test.js`, `tests/pet-geometry.test.js`에 있습니다.

실제 연결된 화면에서 수행한 자동화 기록은 `qa/multimonitor-native.json`에 보관합니다. 실행 환경은 macOS Apple Silicon이며 다음 두 디스플레이가 연결되어 있었습니다.

| 디스플레이 ID | 전역 경계 DIP | 배율 |
| --- | --- | --- |
| 2 | x=0, y=0, 2560×1440 | 1 |
| 1 | x=2560, y=0, 2560×1440 | 1 |

이 환경에서 디스플레이 **2 → 1 → 2** 이동, 대상 작업 영역으로의 창 이동, 포인터 캡처 소실 후의 처리, 놓은 뒤 드래그 해제와 클릭 통과 복원을 확인했습니다. 디스플레이별 작업 영역의 높이가 다른 경우도 기록에 포함되어 있습니다.

음수 원점의 왼쪽·위쪽 모니터, 서로 다른 화면 배율, 모니터 사이 간격, 작은 작업 영역, 경계·동률 선택은 **단위 테스트의 가상 배치**로 검증했습니다. 해당 구성을 실제 하드웨어에서 실행했다는 뜻은 아닙니다. Windows와 Intel Mac에서는 이번 드래그 변경을 네이티브 실행으로 검증하지 않았습니다. 패키지 생성·실행 결과는 `QA.md`를 확인하세요.

## 자동화 입력의 한계

CUA의 앱 상대 좌표 드래그는 드래그 도중 창의 전역 원점이 바뀔 때, 놓기 이벤트의 전역 좌표에 새 원점이 중복 반영되는 현상이 관찰되었습니다. 예를 들어 오른쪽 화면으로 이동한 뒤 로컬 x=3100으로 발생한 놓기 이벤트가 전역 x=5660으로 보고되어, 최종 위치가 화면 여백으로 보정되었습니다.

따라서 이 자동화 기록은 모니터 전환과 드래그 수명주기 처리를 확인하는 증거이며, 물리적 마우스 포인터와 최종 캐릭터 위치가 모든 구간에서 정확히 일치한다는 증거로 사용하지 않습니다. 이 도구의 좌표 문제를 보정하기 위한 예외 처리는 앱에 넣지 않았습니다. 실제 이벤트는 네이티브 전역 좌표와 메인 프로세스의 커서 조회 결과를 그대로 사용합니다.
